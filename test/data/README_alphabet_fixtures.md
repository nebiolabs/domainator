# Nucleotide alphabet fixtures

These back the DNA/RNA tests in `test_hmmer_build.py`, `test_hmmer_search.py`,
`test_hmmer_compare.py`, `test_hmmer_select.py`, `test_hmmer_report.py` and
`test_utils.py`. All of the sequence data is synthetic, so nothing here depends on an
external database.

## Alignments

`dna_msa_1.afa`, `dna_msa_2.afa`, `dna_msa_3.afa` and `rna_msa_1.afa` are 12 sequences of
72 aligned columns each, generated by the script below. `dna_msa_2` is a 12% diverged copy
of `dna_msa_1`, so the two profiles score as a real hit; `dna_msa_3` is unrelated, so it
falls below the score cutoffs. `rna_msa_1` is `dna_msa_1` transcribed, which is why the RNA
scores match the DNA ones exactly.

Alignments need enough columns for pyhmmer to infer an alphabet (roughly 8+) and enough
sequences that the emissions are not dominated by the prior, hence 72 and 12.

```python
import random
from pathlib import Path

BASES = "ACGT"
L, NSEQ = 72, 12

def mutate(seq, rate, rng):
    return "".join(
        rng.choice([b for b in BASES if b != base]) if rng.random() < rate else base
        for base in seq
    )

def write_afa(path, root, rate, prefix, rng):
    lines = []
    for i in range(NSEQ):
        lines.append(f">{prefix}_{i+1}")
        lines.append(root if i == 0 else mutate(root, rate, rng))
    Path(path).write_text("\n".join(lines) + "\n")

rng = random.Random(20260908)
root1 = "".join(rng.choice(BASES) for _ in range(L))
root2 = mutate(root1, 0.12, rng)   # diverged relative of family 1
root3 = "".join(rng.choice(BASES) for _ in range(L))  # unrelated

write_afa("test/data/dna_msa_1.afa", root1, 0.05, "dna1", rng)
write_afa("test/data/dna_msa_2.afa", root2, 0.05, "dna2", rng)
write_afa("test/data/dna_msa_3.afa", root3, 0.05, "dna3", rng)

rna = Path("test/data/dna_msa_1.afa").read_text().replace("T", "U").replace(">dna1", ">rna1")
Path("test/data/rna_msa_1.afa").write_text(rna)
```

## Profiles

Built with domainator's own `hmmer_build.py` rather than HMMER's `hmmbuild`, so the
fixtures match what the tool under test emits and so NAME/ACC/DESC are set explicitly.
Run from the repository root:

```bash
for n in 1 2 3; do
  python -m domainator.hmmer_build -i test/data/dna_msa_$n.afa --alphabet dna \
      --name dna_prof_$n --acc "DNA0000$n" --desc "synthetic DNA profile $n" \
      -o test/data/dna_profiles_$n.hmm
done
cat test/data/dna_profiles_1.hmm test/data/dna_profiles_2.hmm test/data/dna_profiles_3.hmm \
    > test/data/dna_profiles.hmm
rm test/data/dna_profiles_2.hmm test/data/dna_profiles_3.hmm  # only _1 is used on its own

python -m domainator.hmmer_build -i test/data/rna_msa_1.afa --alphabet rna \
    --name rna_prof_1 --acc RNA00001 --desc "synthetic RNA profile 1" \
    -o test/data/rna_profiles.hmm
```

Written profiles carry `DATE` and `COM` lines that record the build time and argv, so a
freshly built profile can never be byte-compared against a committed one. Assert on
content instead (`"ALPH  DNA" in text`, `"MAXL  500" in text`, and so on).

## Expected output

`dna_profiles_hmm_scores.tsv` is the DNA counterpart of `pDONR_201_hmm_scores.tsv`,
regenerate it only if the scoring or the alignment midline changes:

```bash
python -m domainator.hmmer_compare -i test/data/dna_profiles.hmm -r test/data/dna_profiles.hmm \
    -o test/data/dna_profiles_hmm_scores.tsv --alignments --score_cutoff 13 --cpu 2
```
